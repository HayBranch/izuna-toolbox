# 泉奈工具箱 · Izuna Toolbox

轻量 Tauri 2 桌面工具箱，核心功能是**悬浮字幕**：一枚像 QQ 音乐歌词那样的透明小窗，
悬浮在游戏/任意窗口上方，实时显示你配置的战绩数据，并且**能被 OBS 等直播软件窗口捕获**。
还支持**B 站直播排队队列**：按正则自动记录谁发了「排队」等弹幕，并在独立的透明弹窗里实时显示名单。

**Tauri 2 + React 19 + TypeScript + Vite 7 + TailwindCSS 4 + SQLite**

## 关于

泉奈工具箱（Izuna Toolbox）是一个免费的开源小工具，为直播玩家打造：
把「打了多少场、胜率多少」这类战绩数据做成一枚可被直播软件捕获的悬浮字幕，
所有数据保存在本地 SQLite 数据库里、不会上传；仅「自动更新」检查版本时会连接 GitHub，
排队队列会连接 B 站获取公开的直播弹幕（不登录、不发送任何内容）。

- 仓库：<https://github.com/HayBranch/izuna-toolbox>
- 许可证：[MIT](./LICENSE)

## 功能

主窗口侧边栏有 **悬浮字幕 / 排队队列** 两个功能页，左下角 ⚙ 设置打开应用设置。
功能页都是两级：**列表**先展示基本信息，点一行进入这套配置的详情，不用跨页切换。

### 🧮 变量与计数（每套浮窗独立）

**每个浮窗就是一套完全独立的配置**：自己的账号、变量、计算变量、模板，互不影响；
都在该浮窗的卡片里直接编辑。

- **自定义变量**：数量不限、显示名随意起（如"总数""人机场次"），
  引用名（A1、A2…）可自定义也可自动分配，每行有 − / ＋ 按行内步长加减；
- **联动跟随**：任意变量可设置跟随本套另一个变量。例如 A1 跟随 A3：
  按 A3 的 −/＋ 时，A1 同步 −/＋ 相同幅度（单向，A1 的按钮不会反向改 A3）；
  支持多级跟随，配置时自动阻止循环引用；
- **计算变量**：写表达式引用**本套内**的其它变量自动算出，支持 `+ - * /` 与括号，
  例如 `A1 + A2`、`A4 / (A1 + A2)`；行内实时预览；
- **格式化**：计算变量可选"普通数 / 百分比"，百分比会把 0.8 显示成 80%，
  小数位数 0~3 位可选；
- 内置变量（自动计算，无需维护）：

| 变量 | 含义 | 示例 |
|---|---|---|
| `{today}` | 今日日期 | 20261116 |
| `{date}` / `{time}` | 日期 / 当前时间 | 2026-11-16 / 21:30 |
| `{account}` | 本套账号 | 泉奈 |

- 首次运行自带一套示例：A1 人机场次 / A2 真人场次 / A3 人机胜场 / A4 真人胜场，
  以及 B1 总场次 = `A1 + A2`、B2 总胜场 = `A3 + A4`、
  B3 总胜率 = `B2 / B1`（百分比，1 位小数）、B4 真实胜率 = `A4 / B1`。

### 🪟 悬浮字幕（配置队列，可多开）

- **浮窗配置是一个队列**：可创建任意多个，各自命名；列表里先看基本信息
  （名称、创建时间、最后修改时间、是否显示、置顶、鼠标穿透），点名称才进入全部配置；
  列表里的状态标签本身就是开关，**显示 / 置顶 / 鼠标穿透不用进详情就能直接切换**；
  配置全部持久化，重启后原样恢复；
- 浮窗右上角悬停会出现 ℹ️ 按钮，悬浮即可查看这套浮窗的名称、创建/最后修改时间、
  显示状态、置顶、鼠标穿透、位置与变量数量；
- **多行换行排版**：模板里回车即换行；开启「自动换行」后超过最大宽度的长行
  也会折行，浮窗尺寸随行数自适应；「示例模板」按钮一键套用多行排版；
- 样式：字号、字体颜色、加粗、描边阴影、背景颜色、**背景不透明度**（0 = 全透明）
- 卡片内有实时预览，所见即所得
- 每个浮窗可单独设置：
  - **显示 / 隐藏**（隐藏 ≠ 删除，配置保留）
  - **窗口置顶**（浮窗右上角悬停也有 📌 按钮可切换；主窗口聚焦时临时取消置顶以免挡住按钮，切走后自动恢复）
  - **鼠标穿透**：开启后浮窗完全不响应鼠标，绝不挡游戏操作（🔒 按钮或主窗口均可开关）
- **手动保存**：详情页改名称 / 账号 / 模板 / 样式 / 变量后，点「保存」或按 **Ctrl+S** 才写入本地 SQLite；
  显示 / 置顶 / 穿透开关、拖动位置、拉伸宽高、变量 −/＋ 仍是即时生效。有未保存修改时
  返回列表或切换页面会弹窗问「保存 / 丢弃 / 取消」
- 直接拖动浮窗调整位置，自动保存；也可在主窗口输入 X/Y
- **宽高直接拉**：鼠标悬停浮窗，按住边缘或四角拖动即可改宽高（自动保存）；
  拖过之后窗口固定为手动尺寸，主窗口「恢复自动尺寸」或浮窗工具条上的 ⤡ 可改回按内容自适应
- 浮窗内容尺寸自适应：改模板、改字号、改行数后窗口自动贴合文字

### 💬 排队队列（B 站直播弹幕，可多开）

每个队列都是一套完全独立的配置，拥有自己的直播间、匹配规则、排序方式与透明弹窗：

- **实时弹幕长连接**：走 B 站直播 WebSocket 协议（自动解析短号、获取弹幕服务器与 token，
  断线自动重连），不是反复请求 HTTP；「刷新间隔」控制的是**命中弹幕批量写入数据库 /
  界面刷新**的频率（1~60 秒），避免高人气直播间一条弹幕刷新一次界面；
- **多个匹配正则**：每行一条，弹幕文本命中任意一条就记一次排队；
- **两种排序**：`发送时间`（先到先得）或 `发送次数`（次数多的在前，同次数先到先得）；
- **独立弹窗**：与悬浮字幕同款透明无边框窗口，可被 OBS 窗口捕获；
  同样支持显示/隐藏、置顶、鼠标穿透、拖动位置、拖边缘改宽高、自动尺寸；
  弹窗最多显示前 N 人（默认 20），超出部分在底部提示；
- **名单管理**（主窗口）：手动添加成员（同名累加次数）、修改次数（−1 / +1 / 精确输入）、
  改昵称、删除单个成员、清空名单；弹幕实时累加与手动修改都是原子更新，不会互相覆盖；
- **按 UID 累计**：同一个人多次发送排队只占一行，次数累加；手动添加的成员 UID 记为 0；
- **手动保存**：详情页改直播间、刷新间隔、匹配正则、排序、弹窗样式后，点「保存」或按 **Ctrl+S**
  才写入本地 SQLite；监听 / 显示 / 置顶 / 穿透开关与成员增删改仍即时生效。有未保存修改时
  返回列表或切换页面会弹窗问「保存 / 丢弃 / 取消」
- 列表里可直接切换 **监听 / 弹窗显示 / 置顶 / 鼠标穿透**，不用进详情；
- 队列状态（已连接 / 连接中 / 连接失败 / 未设置直播间 / 已暂停）每 5 秒刷新，
  连接失败的具体原因显示在配置页顶部；
- 直播间必须正在开播；连接失败（例如 B 站风控、直播间不存在）会自动重试；
- **B 站登录（获取真实 uid / 昵称）**：游客连接下 B 站会把弹幕 uid 置 0、昵称打码
  （连接约 30 秒后生效，所以游客模式开头几条可能是真实身份、之后变匿名，这是服务端行为）。
  在「设置 → 开发者选项 → B 站登录」粘贴浏览器请求头里的完整 Cookie（需含 `SESSDATA`
  与 `buvid3`，保持原样的 URL 编码）。连接时先用 Cookie 请求账号接口取得 mid，再以
  `uid=mid`、`buvid=Cookie 里的 buvid3` 鉴权（与 blivedm 一致）；账号接口判定未登录时自动
  回退游客连接并写明原因。连接后若服务端 120 秒内一条通知都不推（心跳仍正常），会判定
  静默停推并自动重连。

### ⚙️ 设置

主窗口左下角的 **⚙ 设置** 按钮打开设置页，分四页（外观 → 开发者选项 → 配置及同步 → 关于）：

- **外观**：自动 / 白色 / 黑色三选一；自动模式跟随系统外观并实时响应变化。
  偏好写在 exe 同目录 `conf/conf.toml` 的 `theme` 项，**不再使用 localStorage**；
- **开发者选项**：调整日志等级（`off` / `error` / `warn` / `info` / `debug` / `trace`），
  默认 `error`（只记错误，基本不打印日志），修改后立即生效并写回 `conf.toml`；
  同时显示配置文件与日志目录路径；
- **配置及同步**：导出 / 导入 `conf.toml`，可选是否连同 SQLite 数据一起打包；
  支持导出到本地或 WebDAV，导入时先看摘要，再选择「覆盖」或「增量」；
  底部还有 **恢复所有默认设置**（只重置外观与日志等级，不删除数据）；
- **关于**：应用介绍、版本、仓库、许可证与「检查更新」，固定放在最后一页。

原生 Windows 标题栏也会跟随主题切换（`core:window:allow-set-theme` 权限），
不会出现白页面配黑标题栏。主窗口「置顶」仍收在左下角，与设置按钮并排。
列表、配置卡、更新弹窗、设置页都有对应的明暗配色；浮窗本身保持透明，不受主题影响。

### 🔄 配置及同步（本地 / WebDAV）

- **导出**：只导出配置时写一份可直接使用的 `conf.toml`；勾选「同时导出数据」
  （默认勾选）则把 SQLite 里的浮窗、变量、计算变量、排队队列与名单一起打包成 JSON；
- **WebDAV**：支持坚果云、群晖、Nextcloud 等兼容 WebDAV 的服务。
  勾选数据时上传 `izuna-backup.json`，否则上传 `conf.toml`；目录不存在会自动逐级创建；
- **导入**：本地或 WebDAV 下载的 JSON / conf.toml 都支持。读取后先展示摘要
  （含配置、浮窗/队列/名单数量），再选择：
  - **增量**（默认）：保留现有数据，只新增本地没有的同名浮窗 / 队列；
    同名队列按 UID 合并名单，次数取较大值、时间取并集；
  - **覆盖**：清空现有浮窗、队列与名单后完全恢复备份（不可撤销）；
  - 可勾选是否同时导入外观 / 日志等级；
- WebDAV 地址、账号、密码只保存在本机 WebView 存储里，**不会**写进 `conf.toml`
  或导出文件。

### 被 OBS / 直播软件捕获

- 浮窗是普通的无边框透明顶层窗口，OBS「窗口捕获」（WGC / BitBlt）均可抓取
- 若想让捕获画面不带透明度（有些直播软件对透明支持不好），把背景不透明度拉到 100% 即可
- 窗口显示时不抢焦点，不会把游戏切到后台

### 💾 SQLite 持久化

- 数据库统一用 SQLite（`rusqlite` bundled 静态编译，无需额外安装），文件名固定 `izuna-toolbox.db`；
- 存放位置由 exe 同目录的 `conf/conf.toml` 中的 `portable` 决定：
  - `portable = false`（安装版默认）→ `%APPDATA%/com.izuna.toolbox/izuna-toolbox.db`
  - `portable = true`（便携版默认）→ exe 同目录 `data/izuna-toolbox.db`，整包可拷走
- 首次运行会自动生成该配置文件；旧便携包如果只有 `portable.flag`，会据此把首次生成的
  `portable` 设为 `true`，之后一律以配置文件为准；
- 表结构：`overlays`（浮窗队列，含每套自己的账号、创建时间与最后修改时间）、
  `variables` / `computed`（套内变量，按 `overlay_id` 归属）、
  `queues`（排队队列：直播间、正则、排序、弹窗样式）与
  `queue_entries`（队列成员，按 `queue_id` 归属，按 UID 累计次数）；
- **初始数据**（默认浮窗名、模板、变量、联动）全部在 `src-tauri/src/store.rs`
  顶部的 `SEED_VARIABLES` / `SEED_COMPUTED` 里配置：空库第一次启动带示范数值，
  之后新建浮窗或变量被删光后的补种都用同一套定义、数值从 0 开始；
- 每次变更即提交，退出无需保存；删除数据库文件即恢复出厂；
- 「设置 → 配置及同步」支持把数据库内容连同 `conf.toml` 导出为 JSON 备份，
  也能从本地或 WebDAV 导入，冲突时可选覆盖或增量合并。

### 📝 日志

- 日志文件固定写在 exe 同目录的 `logs/`，与数据库放哪无关；
- **按本地日期分文件**：文件名为 `izuna-toolbox-YYYY-MM-DD.log`。同一天内重启一律追加，
  应用跨天运行时自动切到新文件；历史日志全部保留，**不会**按大小删除或覆盖
  （因此文件数量会随使用天数增长，需要时请手动清理）；
- 日志等级由 `conf/conf.toml` 的 `log_level` 控制，可选 `off` / `error` / `warn` /
  `info` / `debug` / `trace`，**默认 `error`（基本不打印日志）**；
- 可在「设置 → 开发者选项」里修改，**立即生效**，无需重启；
- 同时输出到开发终端与 WebView 控制台（DevTools 里可看）。
- **弹幕登录排查**：「开发者选项 → 弹幕连接排查」会把等级调到 `debug` 并打开日志目录。
  日志会分别记录三件容易混淆的事——Cookie 字段是否解析成功、B 站账号接口
  （`x/web-interface/nav`）是否认可这份 Cookie、弹幕房间鉴权（op=8）是否通过；
  另含 WebSocket 握手状态、每条弹幕的真实 / 匿名身份、每分钟统计里的
  `真实uid / 匿名uid0` 计数。若登录连接收到 `LOG_IN_NOTICE`，日志会明确写出“服务端未认可
  登录态”。日志**不会**写入 Cookie、SESSDATA、弹幕 token 明文。

- **修复多队列计数卡住与浮窗死锁**：多队列计数卡住、弹窗在重启后无法显示等死锁问题已修复，
  并补充弹幕连接日志与排查入口；
- **日志改进**：日志按天追加保留，时间戳改用本地时区（修复此前比北京时间慢 8 小时），并补充

### v0.1.3

- **悬浮字幕 / 排队队列改为手动保存**：详情页的名称、账号、模板、样式、变量、
  直播间、匹配正则、排序、弹窗样式不再边改边写库，改成点「保存」或按 **Ctrl+S**
  一次性写入本地 SQLite；开关、拖动位置、拉伸宽高、变量 −/＋、成员增删改仍即时生效。
  这样改到一半的草稿不会被误存，也不会因为防抖窗口把刚拖好的位置弹回去；
- **未保存修改离开提示**：详情页有未保存修改时，返回列表或切换左侧导航（悬浮字幕 /
  排队队列 / 设置）会弹窗询问「保存 / 丢弃修改 / 取消」，避免辛苦改的内容悄悄丢掉；
- **彻底修复「更新安装完成后不自动启动」**：旧看门进程只能靠「旧进程退出 + exe 能打开 +
  写入时间稳定」猜安装是否结束，而安装器还没开始写文件时这些条件就已满足——抢先启动的
  旧实例随后会被安装器的 RestartManager 强制关掉，结果装完什么都不剩。现在改由安装包
  内置的 `NSIS_HOOK_POSTINSTALL` 钩子负责：`/UPDATE` 更新模式下文件全部落盘后，由安装器
  自己拉起新版程序。这是整条链路里最确定的时机，不依赖任何轮询，也就不再需要外部看门脚本；
- **发布产物精简为 exe + 便携包**：不再构建 / 上传 MSI（CI 上 WiX 常失败，且没有安装钩子）；
  应用内更新只识别 NSIS 安装包，Rust 侧下载校验同步收紧为 `*-setup.exe`；
- **开发者选项新增「测试自动启动」**：不退出当前程序、不改动已安装文件，延迟 3 秒后带
  探针参数再启动一份当前程序；新进程连回当前窗口即判定启动链路正常。

## 与体积有关的打包设计

老项目（tauri-toolbox）用 `"targets": "all"`（NSIS + MSI 一起打）且默认带 WebView2 引导器，
产物又多又大。本项目全部按"现代设备"精简：

| 措施 | 位置 | 效果 |
|---|---|---|
| 只打 NSIS 安装包 | `tauri.conf.json` → `bundle.targets: ["nsis"]` | 发布物只有安装包 exe + 便携 zip，不再构建 MSI |
| 跳过 WebView2 安装 | `bundle.windows.webviewInstallMode.type: "skip"` | Win10/11 都自带 WebView2，不再打包引导器 |
| SQLite 静态编译 | `Cargo.toml` → `rusqlite` (`bundled`) | 数据库直接编进 exe，约 +1MB，免安装免服务 |
| release 全套瘦身 | `Cargo.toml` → `lto + strip + opt-level "s" + panic abort` | exe 最小化 |

> 兼容性兜底：如果将来要给一台**没有 WebView2** 的旧机器用，把 `webviewInstallMode`
> 改回 `{"type": "downloadBootstrapper"}` 重打即可。

## 自动更新（GitHub Releases）

v0.0.7 起支持从本仓库的 GitHub Release 检查并更新：

- 「关于」弹窗点 **检查更新**：请求 GitHub `releases/latest`，比对版本号后列出
  可下载的安装包（NSIS 安装包）与更新说明，可下载后一键安装；
- 启动时也会**静默**检查（可关）：开关在更新弹窗底部「启动时自动检查更新」，
  12 小时内不重复请求，避免触发 GitHub 未认证接口 60 次/小时限额；
- 国内 GitHub 可能连不上：检查自带 **8 秒超时**、失败不卡界面；下载在连接阶段
  整体 **10 秒**、数据阶段每 **15 秒**无数据判超时；**取消下载**随时生效——即使
  线路卡死不出数据也能在半秒内中止并清理半成品；
- 下载在 Rust 侧完成（release 资源跳转的 CDN 不允许前端跨域读取），完成后点
  「立即安装并退出」会**原地替换安装**并退出本程序：NSIS 安装器以 `/UPDATE /P`
  （更新模式 + 被动进度页）启动，不运行旧版卸载器、不删除/重建桌面与开始菜单
  快捷方式——桌面图标及其摆放位置原样保留；被动模式会跳过安装器的「完成后运行」
  页，所以装完的自动重启由安装包里的 NSIS 钩子负责：`src-tauri/windows/hooks.nsh`
  的 `NSIS_HOOK_POSTINSTALL` 在文件全部落盘后直接拉起新版程序（只认 `/UPDATE`，
  首次安装仍由完成页的「运行」勾选框负责）。v0.1.3 起只发布 NSIS 安装包，因此不再
  需要外部看门脚本。「设置 → 开发者选项 → 测试自动启动」可随时自检启动链路；
- 连不上时也能直接点「打开发布页」用浏览器手动下载；
- 下载线路（v0.0.8）：更新弹窗里可选 **加速下载①~③** 或 **直连 GitHub**，
  加速镜像**实时**取自 [xiake.pro](https://xiake.pro/github/) 节点榜按延迟排序的
  前三个（站点无 CORS 头，由 Rust 侧拉取解析），把完整下载链接拼在镜像前缀后面；
  榜单拉取失败时退回内置兜底线路，某条线路慢/失效时切换或直连重试即可，选择会被记住；
- 安装向导为**简体中文**（v0.0.8）：NSIS 启用 `SimpChinese`。

当前版本号显示在主窗口**左上角**（图标下方）与「设置 → 关于」页面里。
开关、线路与检查时间戳存在 WebView 的 `localStorage`（与「窗口置顶」偏好一致），
不写入 SQLite；自动更新主要面向 Windows 安装版，便携版建议从发布页手动下载。

## 快速开始

前置条件：Rust stable、Node.js 20+、Windows 10/11（自带 WebView2）。

```bash
npm install        # 装前端依赖（一次）
npm run tauri dev  # 开发模式：前端热更新 + Rust 自动重编
npm run bundle     # 打包：release exe + NSIS 安装包
npm run bundle:portable  # 打包：便携版目录 + zip（dist-portable/）
```

产物位置：

| 产物 | 位置 |
|---|---|
| 绿色单文件 exe | `src-tauri/target/release/izuna-toolbox.exe` |
| NSIS 安装包 | `src-tauri/target/release/bundle/nsis/` |
| 便携版目录 | `dist-portable/Izuna-Toolbox-<版本>/` |
| 便携版 zip | `dist-portable/Izuna-Toolbox-<版本>-portable-x64.zip` |

便携版解压后双击 `Izuna Toolbox.exe` 即可运行。包内已带 `conf/conf.toml`（`portable = true`），
数据在同目录 `data/`，日志在同目录 `logs/`；把 `portable` 改成 `false` 即改用 `%APPDATA%` 存储。
GitHub Actions 打 tag（`v*`）时会把 NSIS 安装包和便携版 zip 一起传到 Release，
手动触发 workflow 时同样可以在 Actions Artifact 里下载。

### 改版本号

版本号**唯一来源是根目录 `package.json`**：

- `src-tauri/tauri.conf.json` 的 `version` 写成 `"../package.json"`，安装包/exe 版本自动跟随；
- 前端通过 Vite 注入的 `__APP_VERSION__` 读取同一个值（关于弹窗显示）；
- `src-tauri/Cargo.toml` 里的 `0.0.0` 只是占位，不参与展示，不用改。

```bash
npm run bump -- 0.0.4   # 只改版本号（同步 package-lock.json），不提交、不打 tag
git commit -am "chore: 版本号改为 0.0.4"
git tag -a v0.0.4 -m "Izuna Toolbox v0.0.4"
git push origin master v0.0.4
```

## 数据流

单一真相在 Rust 的 SQLite：主窗口/浮窗/排队弹窗的所有修改都走 invoke 命令 → 提交数据库 →
`emit("config-changed")` 广播全量配置 → 各窗口监听事件刷新 UI。
拖动浮窗/排队弹窗由 Rust 侧 `Moved` 事件回写位置（节流广播 `overlay-moved` / `queue-moved`），前端零感知。
B 站弹幕由 Rust 侧每个队列一条 WebSocket 任务实时接收，命中规则后按队列的刷新间隔
批量写入 SQLite 并广播；弹幕连接状态只在内存里，主窗口每 5 秒查询一次。
